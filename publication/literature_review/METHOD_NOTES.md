# Evidence notes: data selection and mixture prediction

Review date: 2026-10-19. These notes record a literature and code review, not a reproduction of the external experiments. Section references below use the formal conference versions. No training or model evaluation was performed.

## Skill-It

**Bibliographic record.** Mayee F. Chen, Nicholas Roberts, Kush Bhatia, Jue Wang, Ce Zhang, Frederic Sala, and Christopher Ré. *Skill-it! A data-driven skills framework for understanding and training language models*. NeurIPS 2023, Advances in Neural Information Processing Systems 36, pp. 36000-36040, DOI `10.52202/075280-1562`. The [formal proceedings record](https://papers.neurips.cc/paper_files/paper/2023/hash/70b8505ac79e3e131756f793cd80eb8d-Abstract-Conference.html) and its [BibTeX](https://papers.neurips.cc/paper_files/paper/21914-/bibtex) list Mayee Chen; the paper title page gives Mayee F. Chen. Formal section numbering differs from arXiv v1.

**Verified paper claims.** A skill is a data-supported behavior whose held-out metric improves after training on its associated slice (Section 3.1, Definition 1). Definition 2 defines an edge by whether the uniform pair mixture needs no more data to reach a target metric than target-only training. The estimated weighted graph instead uses fixed-budget losses: pair versus target-only loss reductions, or the cheaper evaluation-loss change after source-only training (Section 4.2; Appendix C.2, Algorithms 2-3). The sampling objective minimizes final average evaluation-skill loss under a fixed sample budget, with a simplified loss-dynamics model; updates use the graph and current evaluation losses (Section 4.3.2; Appendix C.1). Continual pretraining, target-subset fine-tuning, and disjoint evaluation-skill settings are explicitly distinguished (Section 4.1/Table 1). LEGO and digit-addition provide synthetic demonstrations. [Formal paper, Sections 3-4 and Appendix C](https://proceedings.neurips.cc/paper_files/paper/2023/file/70b8505ac79e3e131756f793cd80eb8d-Paper-Conference.pdf).

**Verified code and reproduction interface.** Reviewed official repository commit `807b3bf7b11970f3a6fb6201cb37dcc1a3335f00`:

- [`dataset/lego_dataset.py`, `LegoDataset._set_lego_graph` and `_generate_skill`](https://github.com/HazyResearch/skill-it/blob/807b3bf7b11970f3a6fb6201cb37dcc1a3335f00/dataset/lego_dataset.py): variables receive binary values; assertions or negations connect variables; names and clause order are shuffled; the query selects a variable. The path depth supplies the default skill index. Path, disconnected, and tree graph options exist. This is substantive procedural generation with known underlying reasoning structure.
- [`dataset/addition_dataset.py`, `_generate_example`](https://github.com/HazyResearch/skill-it/blob/807b3bf7b11970f3a6fb6201cb37dcc1a3335f00/dataset/addition_dataset.py): operands are generated, their exact sum is computed, and a requested digit is the label. The configuration controls digit count and sampling proportions.
- [`trainer/mw_trainer.py`, `MWTrainer.train`](https://github.com/HazyResearch/skill-it/blob/807b3bf7b11970f3a6fb6201cb37dcc1a3335f00/trainer/mw_trainer.py): loads a supplied graph, evaluates losses, updates mixture weights using graph-weighted loss history, and logs distributions.
- [Official README, “How to run” and “Notes”](https://github.com/HazyResearch/skill-it/blob/807b3bf7b11970f3a6fb6201cb37dcc1a3335f00/README.md): provides synthetic/Natural Instructions scripts for pretraining, fine-tuning and out-of-domain settings. It explicitly says graph-learning code is not supplied and illustrates how to estimate an edge using pair-mixture and target-only runs. That limited omission does not imply the paper lacks a defined estimation procedure.

**Comparison boundary.** Synthetic tasks, known generative structure, empirical task dependencies, and budget-controlled data selection already exist here. PermWorld should distinguish a model-independent answer-relation record from a training-response edge. A repository-wide schema separating exact single-answer identities, joint answer derivations, transformed-input queries and proof status was **not verified** in this review; this is not a claim that such annotation could not be added.

## DoGE

**Bibliographic record.** Simin Fan, Matteo Pagliardini, and Martin Jaggi. *DOGE: Domain Reweighting with Generalization Estimation*. ICML 2024, PMLR 235, pp. 12895-12915. [Formal proceedings record](https://proceedings.mlr.press/v235/fan24e.html).

**Verified paper claims.** DoGE learns domain sampling weights with a proxy model, then samples a base model's data using averaged weights. Its generalization score uses source/target gradient inner products; the outer objective concerns target loss, with a first-order approximation and multiplicative update (Section 2, Equations 1-6; Appendix B). Out-of-domain targets are absent from source parameter-update data but supply target gradients for weight estimation (Algorithm 2). Section 3.2/Table 3 also evaluates target fine-tuning: SlimPajama source-pretrained models receive 1,000 target updates. Thus target adaptation is already present. Appendix D.1 records limitations for some target domains relative to the target-access oracle; Appendix E studies stage-wise sampling with matched expected domain exposure. These relations describe model-dependent learning responses, not exact functions of common objects. [Formal ICML paper, Sections 2-3 and Appendices B/D/E](https://raw.githubusercontent.com/mlresearch/v235/main/assets/fan24e/fan24e.pdf).

**Verified code and exposure reporting.** Reviewed official repository default branch `master`, commit `88400e9263dfdd69a24b28aec8533fcb1bf9363d`:

- [`src/trainer.py`, `update_domain_weights` and `update_domain_weights_distributed`](https://github.com/Olivia-fsm/DoGE/blob/88400e9263dfdd69a24b28aec8533fcb1bf9363d/src/trainer.py#L590): computes a matrix of source/target gradient products and updates domain weights. The distributed routine logs per-domain loss, average/current weights, gradient norms, and `sample_count` (lines 772-788). The implementation therefore already contains exposure-related logging.
- [`config/doge_ood/arxiv_ood.json`](https://github.com/Olivia-fsm/DoGE/blob/88400e9263dfdd69a24b28aec8533fcb1bf9363d/config/doge_ood/arxiv_ood.json): specifies six source domains separately from the arXiv target, seed, sequence length, learning rate, update count and evaluation frequency.
- [Official README](https://github.com/Olivia-fsm/DoGE/blob/88400e9263dfdd69a24b28aec8533fcb1bf9363d/README.md) links scripts for universal generalization, SlimPajama/Wiki40b out-of-domain settings, and base-model training.

**Comparison boundary.** PermWorld cannot claim that held-out targets, adaptation, domain dependency estimates or sample-exposure logs are missing from DoGE. Its proposed distinction is explicit mathematical label semantics and query requirements combined with controlled transfer measurement. A theorem/joint-answer/query-transformation registry and deduplicated unique-input exposure accounting were **not verified** for DoGE.

## Data Mixing Laws

**Bibliographic record.** Jiasheng Ye, Peiju Liu, Tianxiang Sun, Jun Zhan, Yunhua Zhou, and Xipeng Qiu. *Data Mixing Laws: Optimizing Data Mixtures by Predicting Language Modeling Performance*. ICLR 2025, pp. 82263-82287. Use this formal author order and year; the earlier arXiv entry orders Zhou/Zhan differently. [Formal proceedings record](https://proceedings.iclr.cc/paper_files/paper/2025/hash/cc84bfabe6389d8883fc2071c848f62a-Abstract-Conference.html), [official BibTeX](https://proceedings.iclr.cc/paper_files/paper/2356-/bibtex).

**Verified paper claims.** The work fits validation loss as a function of training-domain proportions, including cross-domain transfer terms (Sections 3.1-3.3, Equations 7-8). Section 4/Algorithm 1 nests training-step, model-size and mixture predictions to estimate `L(N, S, r)` from smaller runs. Thus it studies composition, budget and model scale together; describing it as a fixed-budget-only mixture study would be wrong. Section 4.2 validates optimized RedPajama mixtures at 1B parameters/100B tokens. Appendix D.2 separately checks step/size extrapolation; Appendix D.3 constrains candidate proportions using available domain tokens. Appendix B explicitly distinguishes the nested pipeline from an unresolved single joint law, and discusses error accumulation, domain definition and dynamic schedules. These are empirical loss models, not mathematical identities among task answers. [Formal paper, Sections 3-4 and Appendices B/D](https://proceedings.iclr.cc/paper_files/paper/2025/file/cc84bfabe6389d8883fc2071c848f62a-Paper-Conference.pdf).

**Verified code and reproduction interface.** Reviewed official repository commit `8ad3e1244b53294ded55a96ae325f4112ce3bc63`:

- [README](https://github.com/yegcjs/mixinglaws/blob/8ad3e1244b53294ded55a96ae325f4112ce3bc63/README.md) points to two-/three-/five-domain fitting notebooks and the prediction pipeline.
- [`pipeline/run.sh`](https://github.com/yegcjs/mixinglaws/blob/8ad3e1244b53294ded55a96ae325f4112ce3bc63/pipeline/run.sh) runs step fitting for 70M/160M/305M/410M models, size extrapolation to 1B at 100,000 steps, mixture fitting, and mixture optimization.
- [`pipeline/find_opt.py`, `dfs` and `find_optimal_ratio`](https://github.com/yegcjs/mixinglaws/blob/8ad3e1244b53294ded55a96ae325f4112ce3bc63/pipeline/find_opt.py) enumerates capacity-constrained mixture candidates and searches predicted loss. The inspected repository offers fitting artifacts/notebooks; a complete clean-room language-model training reproduction was not attempted.

**Comparison boundary.** PermWorld's finite task-count/budget interaction is a different experimental object from predicting corpus-mixture losses across model scales. It supplies no universal scaling law and no validated data-selection optimizer. Full per-example unique-input exposure accounting and an exact-answer relation registry in Data Mixing Laws remain **not verified**.

## Implications for the DMLR framing

These are data-selection or performance-prediction methods with experimental resources, rather than interchangeable task-library benchmarks. Their domain/skill counts should not be ranked against PermWorld template or parameter-instance counts. The defensible contribution is a particular research object: exact functions on the same permutation, with explicit relation/query semantics, evaluated under controlled composition, token budgets and target adaptation. It is not the invention of synthetic generation, task dependence, transfer evaluation, data-mixture studies or logging.

Three claims require separate evidence: an exact formula establishes answer derivability; source evaluation establishes whether a trained model learns that source; target adaptation measures transfer. Neither of the first two entails the third. This separation is a scientific design choice, not evidence that a model actually uses the annotated formula.
