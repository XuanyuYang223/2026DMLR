# PermWorld v0.1: Mathematical Tasks, Relations, and Finite Implementation Certificates

This directory verifies task definitions without running training or using calibration development results to choose tasks or formulas. v5's non-replication and uncertain results remain unchanged; no background variants for the two previous targets are added here.

The machine-readable entry point is [RELATIONS.json](RELATIONS.json); the verification entry point is [CERTIFICATE.json](CERTIFICATE.json). New and legacy tasks share `permworld_platform.label(task_id, p, params=...)`. A permutation is `p=(p₁,…,pₙ)`, with both positions and values in `1…n`. Legal platform lengths are `1…30`; parameterized counting tasks accept `k=1…30`, returning exactly zero when `k>n`.

## Templates, instances, and equivalence classes are counted separately

The three engineering families contain **16 templates and 24 declared parameter instances**. The fixed-length constant/nonconstant counts below apply to default parameters `k=1,2,3` and this round's data lengths **n=8,10,12**; they are not claimed to hold at every legal length. The sole active input encoding is `one_line_v1`; encodings do not increase the mathematical task count. The new families organize and generalize some existing labels, so the 16 templates cannot all be called new mathematical tasks.

| Family | Templates | Parameter instances | Constant instances at fixed length |
| --- | --- | ---: | ---: |
| Cycle decomposition | cycle_count, nontrivial_cycle_count, even_cycle_count, odd_cycle_count, cycle_length_count(k), longest_cycle | 8 | 0 |
| Global subsequences | lis_length, lds_length, increasing_subsequence_count(k), decreasing_subsequence_count(k), rsk_shape | 9 | 2 |
| Permutation blocks | components, global_descents, largest_component, smallest_component, component_length_count(k) | 7 | 0 |

Each of the four parameterized templates declares `k=1,2,3`; these are instances, not four times as many new templates. Existing `shortest_cycle` is retained and verified, but is not added simply to increase the six-template cycle-family count. The legacy `two_cycle_count` and `three_cycle_count` endpoints remain callable as existing parameter aliases of `cycle_length_count(k)`.

[EQUIVALENCE_AUDIT.json](EQUIVALENCE_AUDIT.json) distinguishes the following conventions:

- Among 24 focus instances, `I₁(p)=D₁(p)=n`, so these two define the same function on the same input. There are therefore **23 distinct functions on the same input** over the full declared domain. At each default length in this round, **22 function classes are nonconstant**. Explicit inputs with different answers are retained for the other 275 instance pairs, ruling out duplicates as same-input functions over the full domain. The sole merged pair has a proof from the definitions.
- Further merging LIS/LDS, I₂/D₂, and I₃/D₃ under **registered input transformations that preserve answer values** yields **20 classes, or 19 after excluding length constants**. This describes the quotient generated by those registered relations, not an exhaustive classification of all possible transformations or answer mappings.
- Allowing the invertible affine answer mapping `components(p)=global_descents(Cp)+1` gives **19 classes, or 18 after excluding constants**. These must not be described as 18 independent information sources; joint identities still exist.
- Relative to the legacy catalog, `cycle_length_count(k=1,2,3)` equals fixed_points, two_cycle_count, and three_cycle_count, respectively; `D₂=length`, where legacy `length` means the inversion count; and `I₂=binom(n,2)−length`. These do not add independent mathematical capabilities.

Small lengths create additional degeneracies. For example, n=1 has only one legal input, so every task is constant at that length; counts with k>n are also identically zero. The count "22" therefore does not apply to all n=1…30 or all runtime parameters, nor does it imply that every finite data pool observes all possible answers. See [DEFINITION_DISTRIBUTIONS.csv](DEFINITION_DISTRIBUTIONS.csv) and the platform data-quality tables for finite per-length distributions and constant observations. The task registry separately records general output bounds and invalid-parameter constraints.

## Exact mathematical definitions

Let the disjoint cycle lengths be `ℓ₁,…,ℓ_c`. The cycle-family answers are `c`, `Σ1[ℓᵢ>1]`, `Σ1[ℓᵢ even]`, `Σ1[ℓᵢ odd]`, `Σ1[ℓᵢ=k]`, and `max ℓᵢ`, respectively. Length-one cycles are included; the shortest cycle is `min ℓᵢ`. These quantities are computed from orbits of the permutation action and must not be replaced by contiguous runs in one-line notation.

A globally increasing subsequence is a set of positions satisfying `i₁<…<i_k` and `pᵢ₁<…<pᵢₖ`; decreasing subsequences reverse the value comparison. `I_k,D_k` count qualifying position subsets, and LIS/LDS are the maximum lengths for which such subsequences exist. Positions need not be adjacent, unlike the pilot's contiguous runs. `rsk_shape` is the partition obtained by RSK row insertion of successive values. It outputs the full row-length sequence, not merely the first row or a partition hash.

Direct-sum blocks use the unique finest decomposition into indecomposable components. Cut at each position `j` satisfying `{p₁,…,pⱼ}={1,…,j}`, including the endpoint `j=n`; differences between successive cuts give block lengths. components counts blocks, largest/smallest_component gives their extreme lengths, and component_length_count(k) counts blocks of length k. global_descents separately counts internal cuts `j<n` where every value on the left exceeds every value on the right. It is neither the ordinary adjacent-descent count nor the direct-sum block count.

## Three forms of relation records

Each executable relation records the original input identifier `p`, the task/parameters of each query, its ordered input transformations, and a safe JSON answer expression. `inverse`, `reverse`, and `complement` denote inversion, reversal of positions, and value complementation `n+1−pᵢ`, respectively. Transformation lists execute left to right. Single-task transformation edges and joint multi-query hyperedges are marked separately. A transformed input may equal the original for symmetric permutations; query arguments need not be numerically different.

| Type | Example | Required queries |
| --- | --- | --- |
| Single task/input transformation | `LIS(p)=LDS(Cp)`; `I_k(p)=D_k(Cp)` | One answer from another task on the complemented input |
| Single task/nonidentity answer mapping | `components(p)=global_descents(Cp)+1` | One transformed-input answer, followed by addition of one |
| Same-input joint relation | `cycle_count=even_cycle_count+odd_cycle_count` | Two task answers for the same p |
| Complete same-input parameter family | `Σ_k k·cycle_length_count(p,k)=n`; likewise for block lengths | All answers for `k=1…n`; k=1,2,3 alone do not satisfy the stated reconstruction requirement |
| Cross-input joint relation | `fixed_points(p)=n−deficiencies(p)−deficiencies(p⁻¹)` | Two input queries to deficiencies, plus known n |
| One-way structured-output mapping | `LIS=shape[0]`, `LDS=len(shape)` | The complete shape gives both scalars; the reverse generally does not hold |

Cycle partition, parity, and length-histogram formulas follow directly from cycle decomposition. Subsequence complement/reversal relations follow from bijections of position subsets; inversion relations follow from transposing points in the permutation plot. Increasing and decreasing pairs partition all pairs of positions, so `I₂+D₂=binom(n,2)`. **This binary partition does not generalize to k≥3**, where mixed ascent/descent patterns also occur.

The block/global_descents relation follows directly from the definitions: an internal direct-sum cut is equivalent to every left value being smaller than every right value. Complementation reverses this ordering, and the block count is the internal-cut count plus one. Inversion preserves invariant initial intervals. Reversal followed by complementation reverses the block order while preserving the multiset of lengths, so the listed block statistics are invariant under those transformations.

The RSK first-row/first-column results use the row-insertion theorem rather than extrapolation from a small enumeration. The original paper presents row insertion, the longest increasing subsequence result for the first row, and the corresponding decreasing result: [Schensted, *Longest Increasing and Decreasing Subsequences*, 1961](https://doi.org/10.4153/CJM-1961-015-3). The platform additionally verifies its shape implementation using a different algorithm. The relation table labels these two results `proved_rsk_insertion_theorem` and the other new identities `proved_from_definitions`; finite implementation checks have separate statuses and ranges.

Evidence categories remain separate:

- **Proof/theorem:** formulas, applicability conditions, and proofs in RELATIONS, including references to original certificates for relations proved in v5.
- **Finite verification:** NEW_RELATION_CHECKS and LABEL_CHECKS verify agreement between the implementation and formulas. Finite success is not treated as a universal proof.
- **Empirical association:** the v4 co-variation in source learning recorded in v5's mathematical catalog is reused with its original data provenance. It is not added to the identity list or used to establish mechanisms.
- **Unchecked:** unregistered joint reconstructions, whether a model computes a formula, and whether families are independent. Absence of a registered relation means unclassified, not "unrelated."

Valid formulas are task relations; violations of input/data roles are a separate matter. The platform isolates data using explicit input-orbit rules and does not automatically label a source function's mathematical ability to help derive a target as leakage. Registering a joint hyperedge also does not imply that training prompts provide joint answers or paired transformed queries.

## Completed verification

The final canonical certificate uses fixed fixture seed `2026101907`: **5,913** inputs exhaust `S₁…S₇`, plus **64** fixed random inputs each at `n=8,10,12`, totaling **6,105**. Counting tasks are checked at every `k=1…n+1`, including the zero-answer boundary for impossible lengths.

| Label/relation | Independent verification method |
| --- | --- |
| Cycle statistics | Treat edges i—pᵢ as an undirected graph and obtain component sizes by union-find, without the production cycle traversal |
| LIS/LDS and I_k/D_k | Enumerate all nonempty position subsets, without the production tails/dynamic-programming algorithms |
| rsk_shape | Local growth-diagram rules on the permutation matrix, without production row-insertion/replacement code |
| Permutation blocks | Test set equality and cross-cut comparisons at each cut, without the production prefix-maximum algorithm |
| New formulas | Compare actual query labels with reconstructed answers from safe expressions point by point |

All checks passed: **17 implementations** (16 focus templates plus retained shortest_cycle), **272,741 independent label comparisons**, and **445,581 pointwise checks of 45 newly registered relations**. The final canonical CPU run took about **10.71 seconds**. Definition-distribution tables retain per-length histograms, majority proportions, and constant flags. Random fixtures are mathematical verification samples, not estimates of the formal training or test distribution.

**The 29 historical v5 relations were not enumerated again.** Only SHA256 hashes of the original relation list, certificate, math_ops implementation, and referenced empirical/unchecked tables were checked; see [HISTORICAL_REUSE.json](HISTORICAL_REUSE.json). The old certificate retains its historical count of 1,601,440 independent label checks, which is excluded from this round's added workload. Two preliminary certificates are retained in subdirectories; the canonical entry remains CERTIFICATE.json in this directory. Preliminary and final label results agree; differences only concern historical-source binding and clarification of query fields.

## Executable interface and reproduction

```python
from permworld_platform.relations import list_relations, evaluate_relation

edge = next(r for r in list_relations()
            if r['relation_id'] == 'fixed_from_two_deficiency_queries')
result = evaluate_relation(edge, (2, 1, 3, 5, 4))
assert result['passed']
```

Answer mappings use an allowlisted JSON AST (query/context, add/sub/mod, sum/len, histogram extrema, and related operations), without `eval` or arbitrary code execution. Some inherited historical inequalities/distributional claims retain only their statements and certificates with `answer_map=null`; the executable interface explicitly rejects them. They are not presented as pointwise reconstruction functions.

Specify a **new directory** for re-verification; the command refuses to overwrite an existing certificate:

```powershell
.venv/Scripts/python.exe -m permworld_platform.certificates --out experiments/platform_v01_recheck/mathematics
```

All fixtures in this directory are used only for labels and formula verification and have never been passed to a model. See the main platform report for limited single-task calibration, development curves, data splits, and encoding support. This directory initiates no transfer search.
