# Existing task catalog and mathematical relation audit

`../TASK_CATALOG.csv` registers only definitions already present in the working tree; no tasks were added and no transfer results were read. It contains 57 rows:48 registered PermWorld endpoints, 4 GraphWorld tasks, 4 MatrixGroupWorld tasks, and one parameterized legacy finite-field linear-function template. The latter three domains are inventoried only; this round trains exclusively on PermWorld.

The 48 registered PermWorld endpoints are not 48 independent mathematical task families. `to_cycle`, `to_lehmer`, `to_inversion_vector`, and `to_reduced_word` convert output encodings of the same permutation object. `two_cycle_count` and `three_cycle_count` are two parameter instances of `cycle_length_count(p,k)`, with k=1 equal to fixed_points. The 32 scalar property tasks also have exact correspondences and additive dependencies; they are not 32 independent statistical replications. Catalog fields `identity_kind`, `mathematical_family`, `parameter_variants`, and `input_encoding_variants` preserve these distinctions. Different n, random seeds, architectures, and input encodings do not count as separate mathematical tasks.

Upstream provides four input representations: one_line, cycle, lehmer, and inversion_vector. The matched-length encoding module in 2026TMLR uses one_line and canonical_cycle. These are representation variants of the same mathematical object; this round retains one_line. Mathematical ranges are recorded for n≥1; some intervals are outer bounds rather than fully attainable support. Historical generators and this round's fixed n=10 further restrict inputs. The v3 generic generator has dedicated balanced constructions for pattern_avoidance and bruhat_leq; not all historical tasks use uniformly random permutation labeling.

`RELATION_AUDIT.csv` includes the 8 originally registered cross-task relations, 9 additional relations directly derived from existing definitions, and 13 inverse-invariant relations. The script checks them on all 5,913 permutations in S1 through S7 and another 2,048 random n=10 permutations, plus 7 additive or encoding identities. Finite enumeration verifies implementation; the mathematical basis of identities comes from their definitions. All formulas use the orientation `right(transform(p)) = left(p) + offset`.

Four target candidates and their relations:

| Target | Designated related task in B | Input transformation | Answer mapping | Statistic |
|---|---|---|---|---|
| fixed_points | anti_fixed_points | C(p)_i=n+1−p_i | Identity | Position-equality count |
| exceedances | deficiencies | I(p)=p⁻¹ | Identity | Position-inequality count |
| left_to_right_minima | right_to_left_minima | R(p)_i=p_(n+1−i) | Identity | One-sided record count |
| longest_decreasing_run | longest_increasing_run | C | Identity | Longest contiguous monotone run |

These cover three actions C, I, R and four specific statistical structures. Fixed_points and exceedances remain within the broad positional family; four independent mathematical task families are not claimed. The existing library has no separate registered ascents task. Double_ascents counts strictly increasing contiguous triples and must not be confused with ascents. Cycle tasks satisfy `cycle_count=fixed_points+nontrivial_cycle_count=even_cycle_count+odd_cycle_count`, but this requires multiple answers and is not an identity answer mapping from a single source.

`REPLACEMENT_RELATION_COUNTEREXAMPLES.csv` provides counterexamples for six proposed replacement pairs: fixed_points/successions, exceedances/recoils, left_to_right_minima/{cycle_count,longest_increasing_run}, and longest_decreasing_run/{left_to_right_maxima,cycle_count}. On all n=7 permutations, each candidate under each of the eight input actions generated by I, R, C has two inputs with equal source answers but different transformed target answers. Thus no deterministic mapping based solely on that source scalar exists under these actions. This does not exclude other mathematical relations, joint-task relations, or more complex input transformations, and does not mean C is mathematically unrelated. In particular, exceedances and recoils share Eulerian marginal distributions, but equal distributions do not imply the designated pointwise inverse identity.

The script imports no Torch, runs no models, and reads no neural-network evaluations or test sets. It imports the vendored mathematical definitions already used in v1. `CATALOG_AUDIT.json` retains source hashes, counts, and timing and verifies comparability to the current upstream snapshot. No AGENTS.md was found in the working tree. Reproduction command from the project root:

