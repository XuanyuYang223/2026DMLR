# Mathematical relations and joint derivability in the current backgrounds

This audit reads only the actual mathematical implementations, frozen v4 compositions, previous relation catalog, and previous source-learning tables. It does not read new v5 training data, checkpoints, or transfer results. It was completed before the confirmation experiments and does not change the two specified contrasts. Historical file SHA256 values were identical before and after that audit.

**The deficiencies background for fixed_points has an exact joint relation across transformed inputs in both B and C. C therefore cannot be described as a control without mathematical relations to the target.** However, none of the 12 v4 compositions determines its target from only its four scalar source answers on the same input. The audit provides an n=10 counterexample for each composition. These conclusions are consistent: they allow different input queries.

## 1. Definitions, notation, and scope

Definitions come from [vendored math_ops.py](../../permworld_pilot/vendor/neurips_permutations/math_ops.py) and correspond to the [v4 catalog](../../pilot_v4_backgrounds/TASK_CATALOG.csv). A permutation is represented in one-line form p=(p₁,…,pₙ), with both positions and values in 1…n.

| Symbol | Actual definition |
| --- | --- |
| F | fixed_points = Σᵢ1[pᵢ=i] |
| AF | anti_fixed_points = Σᵢ1[pᵢ=n+1−i] |
| E | exceedances = Σᵢ1[pᵢ>i] |
| D | deficiencies = Σᵢ1[pᵢ<i] |
| d | descents = Σᵢ₌₁ⁿ⁻¹1[pᵢ>pᵢ₊₁] |
| recoils | d(p⁻¹): descents between adjacent values in the inverse-position sequence |
| LIR / LDR | Length of the longest contiguous strictly increasing/decreasing interval, not the longest subsequence |
| peaks | Number of internal positions i with pᵢ₋₁<pᵢ>pᵢ₊₁; endpoints excluded |
| successions | Number of adjacent differences pᵢ₊₁−pᵢ=1; differences of −1 excluded |
| left_to_right_maxima | Number of strict new maxima when scanning left to right, including the first position |

I denotes inversion, R reversal, and C value complementation pᵢ↦n+1−pᵢ. Bit strings follow v4: apply I, then R, then C, so 100=I, 001=C, 110=R∘I=I∘C, and 111=C∘R∘I.

Here, answer derivability means: **given n and only the listed scalar source-task answers, does a deterministic answer map exist that is correct for every p∈Sₙ?** This differs from computing the target with the full input p, which already determines every mathematical label. Nor do we equate neural learning of a source task with access to an exact external query oracle.

We audit two query models separately:

1. Same-input queries: the four source answers on the same p, giving four numbers.
2. Eight-transform queries: answers for all four sources on the eight transformed inputs generated by I/R/C, arranged in action/task order, giving 32 numbers. This is a strictly specified hypothetical query condition, not the actual training prompt format.

## 2. Explicit formulas and proofs

The machine-readable inventory is [RELATION_INVENTORY.csv](audit/RELATION_INVENTORY.csv): 28 identities/bounds and one equal-distribution proposition with a distribution assumption. The relations most relevant to the current compositions are summarized below.

**Position partition and reconstruction across inputs.** Each position is exactly on, above, or below the diagonal. Thus, for every n≥1:

```text
F(p)+E(p)+D(p)=n.
```

Let j=pᵢ. The condition pᵢ>i is equivalent to p⁻¹ⱼ<j, a pointwise bijection of permutation-graph points. Hence E(p)=D(Ip), and substitution gives:

```text
F(p)=n−D(p)−D(Ip).
AF(p)=F(Cp)=n−D(Cp)−D(ICp).
```

This separates three questions. With E and D labels on the same input, F is directly computable from two sources. The current group has D but not E, so that same-input conclusion does not apply. If two exact queries of D on p and Ip are allowed, F is again computable. Both B and C in g2 contain D and satisfy the third condition.

**Direct transform relations for the B candidates.** F(p)=AF(Cp)=AF(Rp) follows from the diagonal/antidiagonal mappings; LDR(p)=LIR(Cp)=LIR(Rp) follows from the bijection of contiguous intervals. All six B compositions therefore recover their targets under eight-transform queries. These relations persist across backgrounds.

**Local comparison structure.** Let sᵢ=1[pᵢ>pᵢ₊₁]. Then d counts the ones in s; LDR is one plus the longest contiguous block of ones; LIR is one plus the longest contiguous block of zeros; peaks counts 0→1 transitions; valleys counts 1→0 transitions. Thus:

```text
peaks+valleys+double_ascents+double_descents=max(n−2,0)
peaks−valleys=s_last−s_first      (define the right side as 0 when n=1)
ceil(n/(n−d)) ≤ LDR ≤ d+1
ceil(n/(d+1)) ≤ LIR ≤ n−d.
```

The first formula partitions internal positions into four states of neighboring comparison bits. The second telescopes transition counts but requires the two endpoint comparison bits. The bounds follow because the longest run is at least the average run length and is limited by the available descent/ascent edges. **Shared computational structure and bounds do not imply that the corresponding scalar labels determine each other.** The v5 LDR contrast replaces d with recoils, removing same-input d; it does not add a co-present descents/recoils pair.

**Successions and common sources.** Each succession is an ascent, so successions(p)+d(p)≤n−1. Transposing the permutation-graph edge (i,a)→(i+1,a+1) gives successions(Ip)=successions(p). Applying the previous bound to Ip yields successions(p)+recoils(p)≤n−1. Replacing descents therefore does not remove all mathematical links involving successions. Also, adjacencies(p)=successions(p)+successions(Cp), partitioning unit adjacent differences into upward and downward cases.

**Other verified identities.** cycle_count=F+nontrivial_cycle_count=even_cycle_count+odd_cycle_count, and parity=(n−cycle_count) mod 2, follow from cycle classification and the sign of each k-cycle. No current composition contains the cycle-source pair needed to recover F, so these identities do not establish a same-input recovery route for the current compositions. Self-symmetries such as peaks(Rp)=peaks(p), successions(CRp)=successions(p), and D(CRIp)=D(p) were independently checked as well.

Descents and recoils are identically distributed under the **uniform distribution on all of Sₙ**, since I is a uniform-measure-preserving bijection. This does not guarantee identical histograms in finite training pools after orbit exclusion, or equal learning speed.

## 3. Joint derivability for each background

Sources are ordered from slot0 to slot3. The B/C candidates are anti_fixed_points/successions for FP and longest_increasing_run/left_to_right_maxima for LDR.

| Target | Common background tasks | Four same-input scalars (B / C) | Eight-transform queries: B | Eight-transform queries: C | Included in confirmation |
| --- | --- | --- | --- | --- | --- |
| fixed_points | g0: descents, peaks, left_to_right_maxima | Both insufficient; n=10 counterexamples | AF(Cp) | Insufficient; n=10 counterexample | Yes |
| fixed_points | g1: recoils, peaks, left_to_right_maxima | Both insufficient; n=10 counterexamples | AF(Cp) | Insufficient; n=10 counterexample | No; audit of earlier exploration only |
| fixed_points | g2: descents, deficiencies, left_to_right_maxima | Both insufficient; n=10 counterexamples | AF(Cp); also n−D(p)−D(Ip) | n−D(p)−D(Ip) | Yes |
| longest_decreasing_run | g0: descents, peaks, successions | Both insufficient; n=10 counterexamples | LIR(Cp) | Insufficient; n=10 counterexample | Yes |
| longest_decreasing_run | g1: recoils, peaks, successions | Both insufficient; n=10 counterexamples | LIR(Cp) | Insufficient; n=10 counterexample | Yes |
| longest_decreasing_run | g2: descents, deficiencies, successions | Both insufficient; n=10 counterexamples | LIR(Cp) | Insufficient; n=10 counterexample | No; audit of earlier exploration only |

Per-condition records are in [TARGET_JOINT_DERIVABILITY.csv](audit/TARGET_JOINT_DERIVABILITY.csv). Every insufficiency claim has an explicit finite counterexample; none infers nonexistence from failing to find a formula. Other input transforms, additional raw input features, and arbitrary algorithmic relations are not exhaustively classified here.

For example, consider two n=10 permutations:

```text
p = (4,10,5,7,8,2,9,6,3,1)
q = (9,4,3,7,2,8,5,6,10,1)
```

For FP g2 B, both (AF,d,D,LTRmax) tuples are (2,5,4,2), but F(p)=0 and F(q)=1. For g2 C, both (successions,d,D,LTRmax) tuples are (1,5,4,2), which also fails to distinguish them. Different F with the same D implies different E, illustrating why one D label is insufficient.

For the five C compositions other than FP g2 C, even all 32 labels for four sources across eight transforms admit n=10 pairs with different targets. The six B compositions and FP g2 C have the recovery formulas above. All 17 counterexamples (12 same-input and five eight-transform) are preserved in [COUNTEREXAMPLES.csv](audit/COUNTEREXAMPLES.csv), checked row by row with both the independent implementation and the original vendor implementation. They rule out universal maps only under these two specified answer-query models, not mathematical relationships in general.

## 4. Keep formulas, empirical associations, and unchecked explanations separate

| Evidence category | Materials | Supported statement |
| --- | --- | --- |
| Definition-level proof | RELATION_INVENTORY, explicit counterexamples, and proofs | Recovery formulas, bounds, or insufficiency under the permitted queries; no model-mechanism conclusion |
| Observed only in earlier data | [OBSERVED_ASSOCIATIONS.csv](audit/OBSERVED_ASSOCIATIONS.csv) | All 12 paired source-development changes for peaks in v4 g1−g0 are negative; LIR also decreases in all three LDR-B blocks. These are co-occurring changes in finite runs |
| Unchecked | [UNCHECKED_CLAIMS.csv](audit/UNCHECKED_CLAIMS.csv) | Whether models compute F=n−D−DI, gradient conflict or mediation by intermediate representations, replication at other lengths, and unlisted joint relations |

This analysis recomputes only 15 differences from previous source-learning tables. It neither fits correlations with target transfer nor makes causal explanations. Frozen confirmation statistics summarize v5 results separately. Proving a task identity, observing co-occurring source-accuracy changes, and confirming replication of a paired background interaction are distinct kinds of evidence.

## 5. Mathematical relations are not automatically data leakage

Current pretraining prompts request one source task at a time. They do not supply target answers, joint four-source answers, or paired transformed-input queries. Different sources may label the same underlying source-training input at different times; that is the multitask design. Orbit isolation prevents the same input or an I/R/C-equivalent input from crossing training, development, and test roles. Each pool retains only one representative per orbit, without explicitly pairing p and Ip. Self-symmetric permutations with Ip=p do not change this policy.

Valid task relations are part of the research question. Violations of frozen role isolation, inclusion of target supervision/test labels, or test-based model/composition selection should be identified separately using evidence. A source function's mathematical usefulness for computing a target is not automatically leakage. Conversely, input isolation does not prove that a model uses no mathematical relations.

## 6. Verification scope and reproduction

[audit_relations.py](audit_relations.py) invokes neither Torch nor models/training. It loads actual vendor label functions and supplies a separate reference implementation: inverse permutations via sorted graph points, runs by enumerating contiguous intervals, and cycles by independent traversal. The reference does not call vendor label functions.

Completed checks enumerate S₁…S₇, totaling 5913 inputs, plus 4096 n=10 definition fixtures generated with Python Random seed=2026101811. Comparing 20 definitions on eight transforms per input gives **1,601,440 label-agreement checks**. Each of 28 formulas/bounds is checked on 10,009 inputs, and descents/recoils histograms match exactly on each exhaustively enumerated Sₙ. All checks passed in approximately 5.14 CPU seconds. Finite checks verify implementations; universal validity rests on the stated proofs, not random testing.

Fixtures are used only for mathematical implementation checks. They are not passed to models, used as formal tests, or used to select targets, compositions, or hyperparameters. Audit outputs refuse overwrites. Use a new directory for independent rechecking:

```powershell
.venv/Scripts/python.exe -B experiments/pilot_v5_confirmation/mathematics/audit_relations.py --out experiments/pilot_v5_confirmation_recheck/mathematics_audit
```
