# PermWorld data-centric pilot

This is an independent minimal transfer pilot. It does not modify or reinterpret alignment results. The code directly reuses task functions, the one-line vocabulary, CausalTransformer, and TMLR's equivalent SDPA implementation from pinned upstream sources. A separate runner handles paired task sampling, data isolation, and adaptation.

## Tasks and freezing

Fix n=10 and uniformly random permutations. The target is `fixed_points`, #{i:p(i)=i}. It was the sole candidate determined before transfer: the mathematical relation is explicit, and TMLR's one-line Transformer reached single-task development accuracy 1.0 at n=10. This round still requires final accuracy ≥0.90 in an independent single-task development experiment. Its 8192 training and 1024 evaluation examples are completely independent of the formal pilot. If it fails, retain the result and stop before the formal stage; do not search for a beneficial replacement target.

- A: random initialization, followed directly by target adaptation.
- B: `anti_fixed_points`, `descents`, `peaks`, `left_to_right_maxima`.
- C: `successions`, `descents`, `peaks`, `left_to_right_maxima`.

`anti_fixed_points(p)=#{i:p(i)=n+1-i}`; `successions(p)=#{i:p(i+1)=p(i)+1}`. Descents counts adjacent decreases, peaks counts strict interior peaks, and left_to_right_maxima counts new records when scanning left to right. All upstream definitions use 1-based permutation values.

The known relation is `fixed_points(p)=anti_fixed_points(c(p))`, where `c(p)(i)=n+1-p(i)`. It is an identity under an input transformation, not equal labels on the same input. Successions is not in the upstream registered direct relation pair for fixed_points; no mathematical unrelatedness is asserted. Under uniform permutations, anti_fixed_points has expectation 1 and successions expectation (n≥1)/n=0.9. Both are approximately Poisson(1), but their distributions are not identical. Empirical histograms, entropy, total variation, and source train/dev performance are recorded; equal difficulty is not assumed.

## Data and comparison conventions

Generate independently for each seed: 8192 distinct pretraining permutations shared by B/C, 1024 source development examples, 1024 target training examples, 1024 target development examples, and 2048 final test examples. Training subsets take the first 64/256/1024 inputs in fixed random generation order and are strictly nested. Within each seed, all three conditions use identical target data, task sampling slots, random initial models, and adaptation random sequences. Data are also isolated across seeds.

All pools, including the independent development pools, exclude complete orbits of up to 8 elements generated by identity, reverse, complement, and inverse. An independent audit checks duplicate inputs and cross-pool orbit intersections. B/C sharing pretraining inputs is intentional pairing, not leakage. No old alignment data or weights are loaded; exhaustive exclusion of every historical input from that project is not claimed. The final test set is used only for a single final evaluation after training ends and the protocol is frozen. It does not select tasks, hyperparameters, or checkpoints.

## Model and budget

Retain the causal Transformer with width 256, 4 layers, 8 heads, MLP ratio 4, dropout 0.1, vocabulary 188, maximum length 128, tied embeddings, and 3,240,448 parameters. Only n=10 is used to keep the pilot small. The input is `<BOS> <SIZE> 10 <ONE_START> ... <ONE_END> <TASK> =`; training appends a single numeric answer and EOS and averages cross-entropy over these two tokens only. Evaluation receives only the prompt and takes answer argmax over all 188 vocabulary entries; EOS is also recorded. The main accuracy is answer-token accuracy.

B/C each use 2400 updates, batch 64, and 16 examples for each of four tasks per batch, shuffled within the batch. Input indices and slots match, giving exactly equal total input tokens. Each condition and target sample size receives 800 adaptation updates × 64 exposures; examples may be reused when comparing distinct sample counts. AdamW uses lr3e-4, betas(0.9,0.999), eps 1e-8, weight_decay0.01, 100 warmup steps, cosine decay to 0.1 of the initial rate, gradient clipping 1, FP32 parameters, CUDA BF16, and TF32 disabled. This is much shorter than the original 20k updates; full mastery of all sources is not guaranteed.

Each adaptation creates a new optimizer without inherited momentum. All task tokens exist from the outset. Before A/B/C adaptation, the tied embedding/output row for the fixed target-task token is restored to the same seed's step0 row. Numeric outputs use the shared language-model head, whose pretrained values are part of transfer. Each sample size starts independently from step0 or its corresponding pretraining endpoint, rather than continuing sequentially. The final checkpoint is fixed, with no development-based selection.

## Reproduction (PowerShell, repository root)

```powershell
uv venv --python 3.13 .venv
uv pip install --python .venv/Scripts/python.exe torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv/Scripts/python.exe numpy==2.5.4 matplotlib==3.11.2
.venv/Scripts/python.exe experiments/permworld_pilot/pilot.py prepare
.venv/Scripts/python.exe experiments/permworld_pilot/pilot.py smoke
.venv/Scripts/python.exe experiments/permworld_pilot/pilot.py develop
.venv/Scripts/python.exe experiments/permworld_pilot/pilot.py freeze
.venv/Scripts/python.exe experiments/permworld_pilot/pilot.py formal
.venv/Scripts/python.exe experiments/permworld_pilot/pilot.py results
```

See requirements-lock.txt for the complete environment. Add the same new `--out experiments/permworld_pilot/runs/replication` to every command when rerunning, to avoid overwriting frozen data. The formal stage skips saved endpoints but does not resume from unsaved intermediate steps. An interrupted individual run restarts; completed results remain. The scripts can run on CPU if CUDA is unavailable, but are substantially slower.

Alternatively, run `.venv/Scripts/python.exe -u experiments/permworld_pilot/run_all.py` to execute the stages above in order and skip completed stages. Post-completion audit commands are `.venv/Scripts/python.exe experiments/permworld_pilot/check_engineering.py` and `.venv/Scripts/python.exe experiments/permworld_pilot/audit_results.py`. Both use saved artifacts and development data only, without test-set forwards.

The smoke test exhaustively checks n=2..7 against 6 independent label definitions and the complement identity. It checks causal isolation from answers, parameter updates, exact save/load, and the full path from real multitask training through optimizer reset and adaptation to prompt-only evaluation. It is not a learning-success gate.

## Outputs and CKA interface

`runs/pilot_v1/` contains the frozen protocol/source hashes, data_audit, raw NPZ files, smoke and independent development records, step0/pretraining/adaptation checkpoints, all loss/dev curves, source_learning.csv, replacement_matching.json, per-seed CSV files, and accuracy curves. Each checkpoint's `model` is a compatible upstream CausalTransformer state_dict with pinned upstream provenance for its configuration and vocabulary. Existing tools can hook block outputs and final_norm at `<ONE_END>` (index 23 for n=10) for later CKA integration. This round does not scan geometric metrics.

Minimal feature extraction example, using 16 development inputs only:

```powershell
.venv/Scripts/python.exe experiments/permworld_pilot/extract_features.py --checkpoint experiments/permworld_pilot/runs/pilot_v1/seed17/adapt_B_256.pt --data experiments/permworld_pilot/runs/pilot_v1/data/s17_target_dev.npz --output experiments/permworld_pilot/runs/pilot_v1/cka_interface_smoke.npz --limit 16
```
